# AI 医生助理 · 多 Agent 系统

给一个真实在用的诊所 AI 助理做的重构：**把「一次调用出答案」改成了有强制校验的流水线。**

- 患者端：微信群里的导诊助理，守「**绝不吐方剂名、急症只劝就医**」这条红线
- 医生端：给执业中医师用的经方助手，可以给方剂名、组成、剂量
- 核心技术点：**多 agent 流水线** + **MCP 协议** + **可回归的红线评测**

> 这个项目里最值钱的不是"用了多 agent"，是**每一个设计决策的取舍理由**——都写在代码注释里。

---

## 它解决什么问题

**改动前**：患者端是一个接口、调一次大模型、直接出答案。
医疗红线全靠一段提示词里写的要求——**模型自不自觉全看它当天的状态**，没有硬约束，也没法测。

| 通道 | 改动前 | 问题 |
|---|---|---|
| 患者端 | 检索 → 单次生成 | 红线**没有强制校验**；改坏了也发现不了 |
| 医生端 | function calling，5 个工具 | 工具分发是 24 行 `if/elif` 硬编码，加一个库就得改代码 |

## 架构

### 患者端：四个 agent 的流水线

```
患者的话
   │
   ▼
① 分诊agent ── 规则优先（急症词命中即判，不调模型）
   │
   ├──急症/危险信号──▶ 直接劝医话术，流程终止
   │
   └──正常──▶ ② 检索agent   同义词扩展 → 向量 → 余弦 TopK
                    │
                    ▼
              ③ 回答agent    守则 + 资料 + 病历 → 草稿
                    │
                    ▼
              ④ 审核agent
                 · 规则层：方名 / 免责 / 急症话术（不花钱，先跑）
                 · 模型层：语义兜底（变相说法）
                    │
            驳回 ◀──┴──▶ 通过 → 输出
         （带问题清单重写，最多 2 次；超限 → 降级成安全话术）
```

### 医生端：一个 agent + MCP

```
医生的话 → 医生端agent ──MCP──▶ 倪海厦知识库 server（5 个工具）
                                  经方 / 本草 / 医案 / 针灸 / 内经
```

## 几个关键设计（取舍都在这里）

### 1. 为什么审核要**独立成 agent**

**自己检查自己等于没检查。**

写话的那个 agent 不负责检查，检查的那个不负责写话。这样审核才能真正挑错。

### 2. 为什么审核要**两层**

- **规则层**（确定性、零成本、先跑）：方名匹配、免责声明、急症话术
- **模型层**（语义兜底）：能听懂「你可以去药店抓点柴胡桂枝煮水喝」这种绕开的说法

**规则层只认字面，模型层会飘——两层各有各的漏，叠起来才够用。**

⚠️ 别把任何一层说成"绝对不会漏"。第一版 README 就是这么吹的，被自己的审查打脸了（见下）。

### 3. 为什么是 **fail-closed**

审核的模型层要调外部 API。**API 会挂**（网络抖、余额没了、限流）。

那么问题来了：**它挂的那一下，这条回复算过还是算不过？**

| | 挂了怎么办 | 后果 |
|---|---|---|
| **fail-open** | 当作通过 | 违规内容**直接发给患者** |
| **fail-closed** | 当作不过 | 打回重写 → 还不行就降级"答不好" |

**本项目用 fail-closed。** 代价是审核一挂所有患者都收到"答不好"——但**这比漏一条红线出去好**。

### 4. 为什么 MCP 取代 if/elif

原来加一个知识库要改三处：import、工具清单 dict、分发分支。

现在加一个知识库 = 在 server 里写一个 `@mcp.tool` 函数，**客户端一行不用改**——因为工具清单是 `list_tools()` 运行时拿的。

### 5. 为什么分诊"规则在前、模型在后"

急症判定**必须是确定性的**——不能今天答对明天答错。而且规则命中就省一次模型调用。

规则只会认字面（患者说"同房**之后有**出血"就漏了），那部分才交给模型。

## 自己审查自己：挖出来的两个严重漏洞

初版写完后，让一个**独立的 agent 只读审查**了一遍（它不参与设计，所以不护短）。它挖出两个会直接上线的漏洞：

**① 审核 fail-open** —— 模型层原来写成：调用失败 / 返回空 / 返回 None，三种情况都 `return "通过"`。
实测一条违规草稿在三种情况下**全部被放行**。**已改成 fail-closed。**

**② 方名清单大面积漏** —— 原来只覆盖 40 个经方名，`六味地黄丸`、`四物汤`、`逍遥散` 这些时方**全拦不住**。
**已改：正则放宽 + 手工补时方清单，40 → 120+ 条。**

顺带修掉：分诊解析过宽（「需要尽快就医」会被降成「正常」）、空草稿能过审、回答/检索异常会打断整条流水线。

### 评测也跟着补了

- **15 条断言式用例**（含 3 条时方陷阱）
- 一条**降级路径**测试：mock 审核永远驳回，验证重写用尽后确实换成安全话术
- **每条用例强制加「回答非空」断言** —— 否则「不含方剂名」这种**否定式**断言对空回答恒成立，答空也能"通过"，那是假通过

```
py 评测\跑评测.py              跑全部（会调模型）
py 评测\跑评测.py --只跑规则    只跑不花钱的
```

## 快速开始

```bash
py -m pip install -r requirements.txt
```

**设密钥**（两种办法，选一个）：

```powershell
$env:SILICONFLOW_API_KEY = "sk-xxxx"   # 硅基流动：取向量用
$env:DEEPSEEK_API_KEY    = "sk-xxxx"   # DeepSeek：对话用
```

或者复制 `config.example.py` → `config.py` 填进去。**`config.py` 不要传上 GitHub。**

```bash
# 规则层自检（不花钱，看方名清单和风险词表）
py 规则.py

# 评测（--只跑规则 不花钱）
py 评测\跑评测.py --只跑规则

# 流水线单跑（看完整执行轨迹和每步耗时）
py 编排.py

# 医生端：列工具（不花钱）
py 医生端agent.py --dry

# 医生端：真实问答（会调模型）
py 医生端agent.py

# MCP server 单独跑（给别人连）
py mcp_倪海厦\server.py          # stdio
py mcp_倪海厦\server.py --http   # HTTP

# LangGraph 版，和手写版对拍
py langgraph版.py
```

## ⚠️ 关于知识库：这里只有样例

`nihaixia_jingfang.py` / `nihaixia_bencao.py` / `nihaixia_yian.py` /
`nihaixia_zhenjiu.py` / `nihaixia_neijing.py`

**每个文件里只有 2-3 条样例**，够让代码跑起来、看清楚格式。

**完整库不公开分发** —— 原始材料是从倪海厦的伤寒论/金匮要略/神农本草经/黄帝内经/医案讲解里蒸馏整理的，医案 1257 例、本草 374 味，体量大且属于他人内容。

**要用完整的**：把你的库整理成同样的格式（一个字符串列表），替换掉对应的变量就行，**代码一行不用改**。

⚠️ 注意：`规则.py` 会从这个列表里**自动抽取方剂名**当患者端禁用词。样例少 → 抽出来的方名就少。真实库上跑出来是 40+ 个。

## ⚠️ 这个项目目前的状态

**这是一个"闭环能跑、但没有上线的参考实现"。** 缺的：

- **没接真实数据库**：记忆/病历由调用方提供（这里是内存里的）
- **没有灰度切换**：真实上线要先在本地证明稳定，再切换入口
- **没有告警**：fail-closed 意味着审核挂了全员降级，但**现在没有任何通知**——只能等用户反馈。这是已知缺口
- 检索没有相似度阈值、向量缓存没设上限
